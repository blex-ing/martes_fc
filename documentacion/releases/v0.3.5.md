# MARTES FC v0.3.5 — Rendimiento de estadísticas y validación D1

## Mejoras
- PR #62 / issue #36: las fichas individuales y Portería reutilizan las estadísticas previamente indexadas por `ranking` en lugar de volver a recorrer el histórico.
- El historial de un jugador o portero se memoriza mientras no cambien su selección ni los encuentros, y Partidos usa un mapa de nombres y un único filtro.
- **No hay cambios visuales** ni CSS, ni migraciones, ni cambios en autenticación o en el contrato `/api/public/snapshot` v2.

## Mediciones verificadas en GitHub Actions
- Para 2.000 encuentros y 7 jugadores sintéticos, la operación aislada de recalcular una ficha tardó 59,32 µs frente a 1,10 µs con la estadística ya calculada (aprox. 54,1× más rápida esa operación; no el render entero).
- La prueba SQL tomó 2,325 ms para consultar 2.000 partidos y 7,892 ms para sus 14.000 participaciones, medianas locales de cinco ejecuciones; **no son medidas de Cloudflare remoto**.
- Se confirma que con 2.350 encuentros publicados solo se devuelve la página histórica estable de los 2.000 más recientes, con participantes y goles correctos y sin registros privados.
- La consulta SQL original se conserva por ser ya eficiente en pruebas locales. El índice de métricas compartido también existía: la mejora consiste en reutilizarlo en las demás vistas.

## Pruebas y documentación
- Nuevas verificaciones SQL reproducibles de 0, 1, 2.000 y 2.350 partidos, respetando orden, límites, privacidad y relaciones.
- Pruebas de equivalencia de estadísticas de jugador/portero con 0, 1, 2.000 y 2.105 encuentros.
- `web/scripts/bench-stats.mjs` y `documentacion/RENDIMIENTO_SNAPSHOT.md` detallan método, resultados y límites.
- CI Chromium/WebKit, lint, TypeScript, auditoría y build Cloudflare obligatorios.

## Alcance futuro
- El snapshot v2 sigue limitado a los 2.000 últimos encuentros, sin paginación. Si hace falta consultar un histórico mayor, se abrirá una feature específica para versionar y probar la paginación sin romper la interfaz ni la API.
- No se accede a D1 producción ni se copian datos entre entornos.
